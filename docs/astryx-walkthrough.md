# Astryx Walkthrough — Slide Spec

**Structure:** one screenshot per slide, caption underneath, back/next navigation.
**Order:** sidebar order, which is also the natural workflow order.

**Narrative spine:** every slide uses the *same target* — Sh2-101 (the Tulip
Nebula) — from first search through to post-session analysis. The user watches
one object travel the entire pipeline. This is what turns a feature tour into a
story, and it costs nothing but consistency in the captures.

Captions are written to be read in ten seconds. Each one states what the user is
looking at and, more importantly, what it saves them from doing by hand.

## Notes on execution

**Capture consistency.** Same theme, same window size, same observer location,
same target throughout. Inconsistency between slides is the single fastest way
to make a walkthrough feel like a screenshot dump rather than a tour.

**Populated, never empty.** Every capture should show real data — a real
session, a real log, a real year of activity. An empty To Do List or a blank
report undersells the app more than any wording can fix.

**Two possible trims.** Twenty slides is long for a website carousel. If it
needs shortening:

- Merge 5 + 6 (Yearly + Daily Visibility) into one "when to shoot it" slide.
- Merge 9 + 10 (Sequence Planner + flip) into one.
- Merge 15 + 16 + 17 into a single "what the report tells you" slide.

That takes it to 16, or 14 if all three merges are applied. The 20-slide version
is the better story; the 16-slide version is the better carousel.

**Alternative structure worth considering.** Instead of one linear run, group
the slides into three labelled acts with a divider between them — *Plan* (2–10),
*Record* (11–13), *Understand* (14–17). Users who only care about one part can
jump straight there, and the three-act shape makes the app's scope legible in a
way a flat twenty-slide run does not.
